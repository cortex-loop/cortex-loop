# Mission Reflection Contract

Surface: internal

This file owns the chat-boundary Cortex Mission Reflection contract.
`AGENTS.md` points here; `internal/workflow/mission_reflection.py` is the
shared renderer and validator used by `repo_workflow.py`, the Claude Code Stop
hook, and the Codex App Stop hook.

Mission reflection is administrative closure. It must not determine the
structure, ordering, or emphasis of the substantive answer. The answer comes
first; the reflection graph closes the turn.

## Modes

Use the smallest mode that matches the turn:

- `exploration` — synthesis, strategy, critique, read-only analysis, and
  "what do we think?" turns. This mode prevents closeout-grade ceremony from
  consuming the answer budget.
- `work` — implementation, probe setup, doc edits, verification, and ordinary
  dirty-branch work.
- `closeout` — `close-session`, `finalize`, publication, or any turn that
  claims landable session closure.

Generate a graph with:

```bash
python3 internal/workflow/repo_workflow.py grid --mode exploration
python3 internal/workflow/repo_workflow.py grid --mode work
python3 internal/workflow/repo_workflow.py grid --mode closeout
```

`work` is the command default for backward compatibility. Do not infer turn
type from git dirtiness alone: dirty branches can still have research-shaped
conversation turns. Choose the mode from the user's actual request.

## Exploration Mode

Required rows:

- `Repo: State`
- `Mission: Cortex target`
- `Mission: Boundary judgment`
- `Decision: Next ownership move`
- `Verdict`

Validation:

- exactly one two-column table under `## Cortex Mission Reflection`
- no `###` subsection inside the graph
- no stale dashboard rows
- no mission-reflection template text left in required rows
- required mission rows are at least 60 meaningful characters
- at least one required mission row cites a repo surface such as
  `docs/CORTEX.md`, `internal/truth/cortex_status.json`, `cortex/**`,
  `tests/**`, or a `CORTEX_V2_*` packet
- `reflection-check --json` must not return `FAIL`

Example:

```markdown
## Cortex Mission Reflection

| Field | Value |
|---|---|
| **Repo: State** | branch `codex/example`; vs origin/main +0 / -0; worktree clean; closeout absent; drift none |
| **Mission: Cortex target** | This exploration served focus by evaluating a process choice against `docs/CORTEX.md` rather than turning the grid into the answer. |
| **Mission: Boundary judgment** | Internal workflow analysis only; no `cortex/**` runtime path or shipping behavior changed. |
| **Decision: Next ownership move** | Keep this as analysis unless the user explicitly opens a workflow-law seam. |
| **Verdict** | Turn verdict: ✅ PASS — mechanical gates clear for this turn. Close-session eligibility: no — no closeout artifact is present. |
```

## Work Mode

Required rows:

- `Repo: State`
- `Repo: Gates`
- all `Mission:*`, `Reflection:*`, `Evidence:*`, and `Decision:*` rows
- `Verdict`

Validation:

- exactly one two-column table under `## Cortex Mission Reflection`
- no `###` subsection inside the graph
- no stale dashboard rows
- no mission-reflection template text left in required rows
- required mission/reflection/evidence/decision rows are at least 120
  meaningful characters
- at least three required mission/reflection/evidence/decision rows cite repo
  surfaces
- `reflection-check --json` must not return `FAIL`

`work` mode intentionally omits `Closure: Metadata`; that row is reserved for
closeout.

## Closeout Mode

Required rows:

- `Repo: State`
- `Repo: Gates`
- all `Mission:*`, `Reflection:*`, `Evidence:*`, and `Decision:*` rows
- `Closure: Metadata`
- `Verdict`

Validation:

- all `work` shape checks
- every required mission/reflection/evidence/decision row cites a repo surface
- every required mission/reflection/evidence/decision row is at least 120
  meaningful characters
- `Closure: Metadata` is filled with ending branch, commit/no commit,
  verification, returned-to-main status, registry/doc-regeneration facts, and
  no `closure metadata —` or `<fill` placeholders
- `reflection-check --json` must not return `FAIL`

Closeout mode is the strict legacy contract and remains the required contract
for managed session closure.

## Forbidden Shapes

The graph must not include:

- fixed dashboard rows such as `Progress:*`, `bio_to_code matrix`, hosts,
  shipping default, current train, next train, or research-line counts
- old closure rows such as `Std:*`, `Mirror:*`, `Goals:*`, `Mech:*`, or
  `Work:*`
- a second table inside the graph
- `###` subsections inside the graph
- hand-written graph-like markdown that did not come from `grid`

## No-Mimicry Rule

Run `grid`, paste the generated markdown skeleton, and fill it in place.
Composing markdown that resembles graph content but was not generated by the
workflow command is a violation. This keeps the renderer, validator, and hook
behavior aligned.

## Closure-Leak Rule

Closure-shaped substrings must not appear in prose before the graph header:

- `Ending branch`
- `Verification summary`
- `Fixed now`
- `Claim earned now`
- `Status registry touched`
- `Closure: Metadata`
- `Final Handoff Mirror`
- `DOGFOOD_SIGNAL`

Use closeout mode when that information is required.

## Chat-Boundary Enforcement

Claude Code uses `.claude/settings.json` to run
`.claude/hooks/cortex_grid_stop_hook.py` on `Stop`. The hook reads the latest
assistant message from the transcript, infers the graph mode from the row set,
runs the matching `grid --mode <mode>` command for corrective output, and
validates the assistant message with `internal/workflow/mission_reflection.py`.

Codex App root chat-boundary enforcement is currently disabled in
`.codex/config.toml` with `[features].codex_hooks = false` because live Stop
repair loops can hide substantive answer content. The hook script remains at
`.codex/hooks/cortex_mission_reflection_stop_hook.py` for direct structural
validation and future reactivation decisions; current Codex App chats use
explicit `grid-validate` fallback.

Enabled hooks fail open only on infrastructure failures: missing transcript,
malformed hook input, or `grid` / `reflection-check` command crash. Agent
non-compliance with a valid graph blocks on enabled hook surfaces. Codex App
currently relies on explicit fallback validation rather than Stop blocking.

## Auto-Loop Rule

When an enabled hook blocks, the agent must continue in the same chat and emit a
valid graph. Enabled hooks do not short-circuit on `stop_hook_active`; every
stop attempt re-runs validation.

On `reflection-check` verdict `FAIL`, continue work until the gate clears.
Do not close-session, finalize, or publish on a failed reflection check.

## Fallback Validation

Codex surfaces that do not load repo-local hooks still validate the final graph
explicitly:

```bash
python3 internal/workflow/repo_workflow.py grid-validate --mode exploration
python3 internal/workflow/repo_workflow.py grid-validate --mode work
python3 internal/workflow/repo_workflow.py grid-validate --mode closeout
```

Omit `--mode` only when the validator should infer mode from graph shape.
